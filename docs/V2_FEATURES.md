# HyperTicket v2 历史版本说明

> 本文保留 v2 的演进背景，不再作为当前部署或客户端说明。现行版本使用 v10 活动目录和统一 React/Tauri 客户端，请优先阅读 [根 README](../README.md) 与 [v10 目录运行手册](catalog-v10-runbook.md)。

## v2 的阶段价值

v2 首次补齐了票品详情、搜索筛选、待支付订单、多张购票、收藏与热门榜，并建立了后续订单和支付重构的基础。

| 能力 | 当时协议 | 当前演进 |
|---|---|---|
| 票品详情 | `TICKET_DETAIL(19)` | 保留，并由活动/场次目录提供更完整信息 |
| 搜索筛选 | `VIEW(4)` | 升级为 v10 活动目录、分区展示和场次筛选 |
| 待支付订单 | `ORDER(5)` / `PAY_ORDER(20)` | 升级为 Redis Streams 异步下单和支付状态机 |
| 多张购票 | `quantity` | 升级为同场多座选择和座位关联 |
| 收藏 | `FAVORITE(21)` / `VIEW_FAVORITES(22)` | 纳入个人中心，并增加活动收藏兼容层 |
| 热门榜 | `HOT_TICKETS(23)` | 演进为首页多个内容分区 |

## 已被替代的内容

- v2 的 19 条、五分类票品种子已由 35 个活动、七分类、70 个场次的 v10 数据替代。
- `tickets` 单表票品模型已演进为 `活动 -> 场馆 -> 厅馆 -> 场次 -> 票档/座位`。
- 旧 `frontend/`、Qt 管理端和“三端同步”描述已经失效。
- 当前用户端与管理端均位于 `clients/`，统一采用 React 18.3 + TypeScript + Vite 6 + Tauri 2。
- 直接同步创建订单的旧流程已被 `QUEUED + request_id + ORDER_QUERY(25)` 替代。
- 直接支付确认已被带幂等键的支付请求、Provider 和状态查询替代。

## 当前升级路径

不要在现有环境重新执行 v2 种子覆盖 v10 数据。需要重建当前业务目录时运行：

```bash
./scripts/migrate-and-seed-v10.sh
```

脚本会备份并清理业务数据，同时保留账号、管理员、联系方式验证、Session 与认证安全配置。具体范围和前置条件见 [v10 目录运行手册](catalog-v10-runbook.md)。
